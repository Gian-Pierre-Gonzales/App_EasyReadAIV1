1. INTRODUCCIÓN

1.1 Propósito

El presente documento describe los requerimientos funcionales y no funcionales del sistema EasyRead AI, una aplicación web de accesibilidad digital asistida por inteligencia artificial, orientada a facilitar el acceso a contenido digital para personas con discapacidades visuales, cognitivas o motoras.

1.2 Alcance

La aplicación permite al usuario autenticarse, adaptar la interfaz según sus necesidades de accesibilidad, navegar mediante comandos de voz y escuchar contenido textual mediante síntesis de voz. La solución está implementada como aplicación web progresiva compatible con navegadores modernos.

1.3 Usuarios objetivo

  • Personas con discapacidad visual parcial o total
  • Personas con dificultades cognitivas o de lectura
  • Personas con limitaciones motoras que dificultan la interacción táctil o con teclado
  • Adultos mayores con dificultades para leer texto pequeño

2. REQUERIMIENTOS FUNCIONALES

RF-01 — Autenticación de usuario
Módulo: Login

El sistema debe permitir al usuario iniciar sesión con correo electrónico y contraseña.

Criterios de aceptación:
  • El sistema valida que los campos correo y contraseña no estén vacíos
  • Al ingresar credenciales válidas, redirige al panel principal (Home)
  • El sistema muestra un enlace de recuperación de contraseña
  • Se muestra pantalla de splash con logo antes del login
RF-02 — Panel principal (Home)
Módulo: Home

El sistema debe mostrar un panel de bienvenida con accesos rápidos a las funciones de accesibilidad.

Criterios de aceptación:
  • Se muestra el nombre del usuario autenticado
  • Se presentan 4 botones de acceso rápido: Alto contraste, Letra grande, Modo Simple, Comando de voz
  • Se presenta una lista de acceso rápido a: Leer información, Asistente de voz, Configuración
  • El usuario puede cerrar sesión desde el panel
RF-03 — Alto contraste
Módulo: Accesibilidad Visual

El sistema debe permitir activar y desactivar el modo de alto contraste visual en toda la aplicación.

Criterios de aceptación:
  • Al activar, la paleta de colores cambia a alto contraste (fondo oscuro, texto claro)
  • El estado del botón refleja visualmente si está activo o inactivo
  • El toggle en Configuración se sincroniza con el botón del Home
  • El modo persiste mientras el usuario navega entre pantallas
RF-04 — Letra grande
Módulo: Accesibilidad Visual

El sistema debe permitir aumentar el tamaño de fuente en toda la aplicación.

Criterios de aceptación:
  • Al activar, el tamaño base de fuente aumenta en toda la interfaz
  • El estado del botón refleja visualmente si está activo o inactivo
  • El modo persiste mientras el usuario navega entre pantallas
RF-05 — Modo cognitivo simplificado
Módulo: Accesibilidad Cognitiva

El sistema debe ofrecer un modo de interfaz simplificada que reduzca la carga cognitiva visual.

Criterios de aceptación:
  • Al activar, el grid de opciones se reorganiza en una sola columna
  • El toggle en Configuración se sincroniza con el botón del Home
  • El modo persiste mientras el usuario navega entre pantallas
RF-06 — Asistente de voz
Módulo: Voz

El sistema debe permitir al usuario navegar y controlar la aplicación mediante comandos de voz.

Criterios de aceptación:
  • El usuario puede activar el micrófono con el botón "Hablar"
  • El sistema transcribe en tiempo real lo que el usuario dice
  • El sistema reconoce y ejecuta los comandos definidos
  • El sistema muestra el estado "Escuchando..." mientras el micrófono está activo
  • El sistema muestra la lista de comandos disponibles en pantalla

Comandos disponibles:
Comando de vozAcción ejecutada
"Ir a inicio"Navega al panel principal
"Leer información"Abre el módulo de lectura
"Configuración"Abre el módulo de ajustes
"Alto contraste"Activa o desactiva el alto contraste
"Letra grande"Activa o desactiva la letra grande
RF-07 — Lector de información
Módulo: Lectura

El sistema debe permitir al usuario leer y escuchar contenido textual con control de tamaño de fuente.

Criterios de aceptación:
  • El usuario puede aumentar (A+), reducir (A-) o restablecer (A) el tamaño del texto
  • El botón "Escuchar contenido" activa la síntesis de voz en español
  • La síntesis de voz lee el contenido completo del artículo mostrado
  • El tamaño mínimo de fuente es 11pt y el máximo es 26pt
RF-08 — Configuración de accesibilidad
Módulo: Configuración

El sistema debe ofrecer una pantalla de configuración con toggles para activar o desactivar opciones de accesibilidad.

Criterios de aceptación:
  • Se muestran 4 opciones: Alto contraste, Subtítulos automáticos, Modo cognitivo simplificado, Compatibilidad con lector de pantalla
  • Los toggles de Alto contraste y Modo cognitivo simplificado están sincronizados con los botones del Home
  • El estado de cada toggle se refleja visualmente de forma inmediata
RF-09 — Encuesta de satisfacción (Escala de Likert)
Módulo: Encuestas

El sistema debe permitir registrar datos del participante y realizar una encuesta de satisfacción con escala de Likert, generando reportes descargables.

Criterios de aceptación:
  • Se solicitan datos del participante: nombre completo (obligatorio), edad (obligatoria, rango 10-120) y tipo de discapacidad (opcional: Visual, Auditiva, Motora, Cognitiva, Ninguna, Otra)
  • La encuesta contiene 7 preguntas con escala de Likert de 5 puntos (Muy en desacuerdo – Muy de acuerdo)
  • Las preguntas se dividen en 3 pasos/pantallas (3+2+2 preguntas) con navegación Siguiente/Anterior
  • El sistema valida que todas las preguntas del paso actual estén respondidas antes de avanzar
  • Incluye campo de comentarios adicionales (opcional) en el último paso
  • Al enviar, se genera un reporte con: barras de progreso por pregunta, promedio general, puntaje máximo y mínimo
  • Se muestra historial de respuestas con nombre, edad y promedio de cada participante
  • El usuario puede descargar un reporte HTML con tablas que incluyen datos de todos los participantes
  • Los datos se almacenan en localStorage para acumular múltiples encuestas
  • Se puede iniciar una nueva encuesta desde el reporte sin perder datos anteriores

3. REQUERIMIENTOS NO FUNCIONALES

RNF-01 — Usabilidad

  • La interfaz debe ser intuitiva y operable con mínima interacción
  • Los elementos interactivos deben tener tamaño mínimo de 44×44px (estándar WCAG 2.1)
  • Todos los botones deben tener etiquetas aria-label para compatibilidad con lectores de pantalla
  • La navegación entre pantallas debe ser inmediata sin recarga de página

RNF-02 — Accesibilidad

  • La aplicación debe cumplir con las pautas WCAG 2.1 nivel AA
  • El contraste de color en modo normal debe ser mínimo 4.5:1
  • El contraste en modo alto contraste debe ser mínimo 7:1
  • La aplicación debe ser compatible con lectores de pantalla (NVDA, JAWS, VoiceOver)

RNF-03 — Compatibilidad

  • La aplicación debe funcionar en navegadores modernos: Chrome, Firefox, Edge, Safari
  • El reconocimiento de voz y síntesis de voz requieren Web Speech API (recomendado: Chrome)
  • La interfaz debe ser responsiva para dispositivos móviles y escritorio

RNF-04 — Rendimiento

  • El tiempo de carga inicial no debe superar los 3 segundos en conexión estándar
  • La navegación entre pantallas debe ser inmediata (sin recarga de página)
  • La síntesis de voz debe iniciar en menos de 1 segundo tras presionar el botón

RNF-05 — Idioma

  • La interfaz y todos los textos deben estar en español
  • La síntesis de voz y el reconocimiento de voz deben operar en idioma es-ES

7. IMPLEMENTACIÓN FUNCIONAL

7.1 Arquitectura de la solución

EasyRead AI está implementada como una aplicación web Single Page Application (SPA) utilizando HTML5, CSS3 y JavaScript vanilla. La arquitectura sigue un patrón de navegación basado en pantallas (screen-based), donde todas las vistas coexisten en un único archivo HTML y se muestran/ocultan dinámicamente mediante JavaScript.

Stack tecnológico

ComponenteTecnologíaJustificación
EstructuraHTML5 semánticoAccesibilidad nativa, roles ARIA
EstilosCSS3 + Variables CSSTemas dinámicos (contraste, fuente)
LógicaJavaScript ES6+Sin dependencias, carga rápida
IconosLucide Icons (CDN)SVG accesibles, ligeros
Voz (TTS)Web Speech Synthesis APISoporte nativo del navegador
Voz (STT)Web Speech Recognition APIReconocimiento en tiempo real

7.2 Módulos implementados

Módulo de autenticación

  • Validación de campos vacíos antes de permitir acceso
  • Transición automática Splash → Login (2 segundos)
  • Enlace funcional de recuperación de contraseña

Módulo de accesibilidad visual

  • Alto contraste: Cambio de paleta mediante CSS custom properties. Fondo oscuro (#000), texto claro (#fff), acentos en morado claro (#BB86FC)
  • Letra grande: Incremento global del font-size base de 16px a 20px, con escalado proporcional en todos los componentes

Módulo cognitivo

  • Modo simplificado: Reorganiza el grid de 2 columnas a 1 columna, reduce información visual, facilita la lectura secuencial

Módulo de voz

  • Reconocimiento (STT): Captura de audio en tiempo real con transcripción inmediata y ejecución de 5 comandos predefinidos
  • Síntesis (TTS): Lectura completa del contenido con velocidad ajustada (rate: 0.9) en español (es-ES)

Módulo de configuración

  • 4 toggles funcionales con sincronización bidireccional con botones del Home
  • Estados visuales inmediatos con animación de transición (0.3s)

Módulo de encuestas (Escala de Likert)

  • Registro de participante: Nombre completo, edad (validación 10-120) y tipo de discapacidad (selector con 6 opciones)
  • Encuesta paginada: 7 preguntas divididas en 3 pasos (3+2+2) con validación por paso antes de avanzar
  • Escala Likert 5 puntos: Muy en desacuerdo (1), En desacuerdo (2), Neutral (3), De acuerdo (4), Muy de acuerdo (5)
  • Generación de reportes: Barras de progreso por pregunta, estadísticas (promedio, máx, mín), historial por participante
  • Exportación: Descarga de reporte en formato HTML con tablas completas incluyendo datos demográficos
  • Persistencia: Almacenamiento en localStorage para acumular múltiples encuestas sin backend
